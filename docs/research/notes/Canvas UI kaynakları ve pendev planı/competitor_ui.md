# UI teardown of multi-viewport / responsive-design browser tools (Polypane, Responsively, Sizzy, Blisk, Safari RDM, Chrome DevTools, newer entrants) — as of October 2026

Scope note: these notes focus on screen layout, viewport chrome, sync, presets/workspaces, criticism and native-vs-Electron status. Pricing is mentioned only where it appears in user complaints. Current versions found: Polypane 31 (29 Sep 2026), Responsively 2.0.0-beta.0 (Sep 20; year inferred as 2026, see gaps), Sizzy 75.6 beta 1 (6 Sep 2026), Blisk 25.0.115.28, Safari RDM (Safari 17+ "simplified" design, still current in Apple's 2026 docs), Chrome DevTools device mode (Chrome 153/154 refresh, October 2026).

## Key Question 1: What screen layout does each tool use (toolbar, URL bar, device panel, viewport arrangement, layout modes, zoom, dark mode)?

### Takeaway
All four third-party tools are Chromium/Electron "browsers" with a top address bar, a workspace of viewports, and a dockable tool panel. Polypane has the richest layout system (Horizontal, Vertical, Canvas, Focus, Split, Full), Responsively 2.0 offers flex-wrap, masonry, focus, and a new free Canvas plus Present mode, Sizzy offers horizontal/vertical/float/center "Responsive" modes plus Focus and Zen, and Blisk uses a fixed desktop-plus-device side-by-side model with a left device panel. Safari and Chrome are single-viewport only.

### Inferences
- The dominant pattern is "browser chrome on top, viewport workspace in the middle, dockable inspector panel". A native macOS competitor would differ most visibly by using a native toolbar/sidebar rather than a web-rendered header.
- Free-canvas layouts are the 2026 trend: Polypane 31 (Sep 2026) and Responsively 2.0 (Sep 2026) both added an infinite canvas with pan/zoom/snapping within weeks of each other, and Solis (native Mac) had draw-and-arrange viewports years earlier. A row layout alone is now table stakes; canvas + focus is the expected pair.
- Polypane's "Focus" quick-switcher (buttons for pane sizes and detected CSS breakpoints) and Chrome's media-query bars are the two UI idioms for surfacing breakpoints inside a single viewport.

## Key Question 2: What is in each tool's viewport header/chrome and which per-viewport actions exist?

### Takeaway
Polypane has the most detailed pane header (name/preset, editable W×H, row of tool icons, plus hover-only actions for remove/reorder/duplicate/focus/scale/rotate). Responsively and Sizzy show device name + dimensions with rotate/screenshot/zoom/close/focus controls. Blisk wraps devices in hardware mockups. Safari and Chrome put rotate/size/zoom/DPR in a single top toolbar rather than per-viewport.

### Cited Findings
- Polypane pane header shows the pane name / device preset, width and height fields, and a row of feature icons (left to right): rulers/grids/columns/rows overlays, screenshots, image overlays, debug overlays, emulation settings, devtools (Polypane elements panel or Chromium devtools). On hover, extra buttons appear: remove pane, reorder panes, duplicate pane, open in focus layout, scale settings, rotate. "Each pane can have a different width, height, zoom level, device emulation, and other per-pane settings." Hover-state image: `https://polypane.app/static/paneheaderhovered-b748898e94942c0b5ecb82d6fc0f12ce.png` — [Intro to panes](https://polypane.app/docs/intro-to-panes/)
- Polypane pane management: a crosshair icon in the header opens the pane in Focus mode; a "+" on hover duplicates "all the settings of the current pane (width, height, emulation settings and more)"; arrow buttons swap a pane with its neighbour (Shift-click swaps with first/last); a small "x" appears "in the top left corner of a pane" on hover to delete it. Panes are added via the "+" at the end, double-clicking between panes, right-click > "Add pane here", or ⌘N (adds at the beginning) — [Manage panes](https://polypane.app/docs/pane-management/)
- Polypane 31 pane headers now display per-pane CPU/memory usage with warnings when thresholds are exceeded, and show lock icons with tooltips on size-constrained panes — [Polypane 31 blog](https://polypane.app/blog/polypane-31-canvas-layout-elements-panel-improvements-and-chromium-155/)
- Responsively: each device preview includes device name and dimensions, rotation, one-click screenshot across all devices, close/remove, and zoom controls; a unified elements inspector works across all displayed devices — [GitHub README](https://github.com/responsively-org/responsively-app). v1.18.0 fixed rotation so non-rotatable devices cannot rotate — [Releases](https://github.com/responsively-org/responsively-app/releases)
- Sizzy: each viewport shows device name and dimensions (example "iPhone 17 Pro 402×874"), a current-session indicator, and controls for screenshot, zoom, rotation and focus mode; real user agents per device — [sizzy.co](https://sizzy.co/)
- Blisk: devices are shown inside phone mockups, DevTools can be opened per device independently — [Creating Blisk devices](https://blisk.io/blog/creating-blisk-devices); [blisk.io](https://blisk.io/)
- Safari RDM: top toolbar only — presets list, Rotate Viewport, Size (editable, in points), Zoom %, Pixel Ratio, Open with Simulator; resize handles on left/bottom/right and corners — [Apple docs](https://developer.apple.com/documentation/safari-developer-tools/responsive-design-mode)
- Chrome: top toolbar only — device dropdown, W/H fields, zoom %, throttle, rotate, more-options (media queries, DPR, device frame, rulers, screenshots); optional device frame drawn around the viewport for supported devices — [Chrome docs](https://developer.chrome.com/docs/devtools/device-mode)

### Inferences
- Polypane's choice to hide destructive/structural actions (close, reorder, duplicate) behind hover keeps the visible header to "identity + size + tools", which is a useful pattern for a dense multi-pane canvas.
- Per-pane resource badges (Polypane 31) are a response to the recurring performance complaints (see Q5); a native app could surface the same data via Activity-Monitor-style indicators.

### Gaps
- No documentation found of Responsively 2.0's exact header icon order or of what happens on hover.
- Sizzy per-device "close" and "duplicate" affordances were not documented in fetched sources.

## Key Question 3: How is sync (scroll, click, navigation) exposed and how is the leading viewport shown?

### Takeaway
Every multi-pane tool syncs scroll/click/navigation by default and exposes a single toggle in the address bar (Polypane: button + ⌘O, right-click to pick which event types sync); none of the fetched docs describe a visual "leader" indicator — the pane you interact with simply drives the others.

### Cited Findings
- Polypane syncs by default: "navigation, scroll, hover, click, keypress, input, change" and can also sync focus. Scroll sync toggles via the address-bar button or ⌘/Ctrl+O; right-clicking the sync button opens a menu to choose which interactions sync or to disable all. Scroll sync works on all scrollable elements in both directions, including nested scrollers. Navigation sync can be disabled per pane from the "network" tab in device options (e.g. compare local vs. live). Polypane disables its sync automatically when Browsersync "ghost mode" is detected because the two fight — [Synced interactions](https://polypane.app/docs/synced-interactions/)
- Polypane 30 (Aug 2026) added synced text selection — [Changelog](https://polypane.app/docs/changelog/)
- Polypane 6.1 "rewritten event sync engine" — [daily.dev mirror of Polypane 6.1 post](https://daily.dev/posts/polypane-6-1-readability-content-chaos-and-rewritten-event-sync-engine-fmor5vhnt)
- Polypane: users can disable syncing for individual clicks via the context menu — [Intro to panes](https://polypane.app/docs/intro-to-panes/)
- Responsively: "Mirrored user interactions" with synchronized navigation, scrolling and clicking, with toggle controls for mirroring — [GitHub README](https://github.com/responsively-org/responsively-app); "all other displayed devices will mirror your actions in real time" (mirror.gif) — [Responsively guide](https://responsively.app/blog/responsively-app-guide)
- Sizzy: "Scroll, clicks, typing, and navigation remain synchronized across all displayed devices until disabled", with toggle controls indicating sync status — [sizzy.co](https://sizzy.co/); changelog mentions "improving sync scroll handling when switching between devices" — [Glink changelog via search](https://glink.so/kitze/sizzy/changelogs)
- Blisk: "built-in URL and scroll sync" so devices follow each other by URL and scroll position — [blisk.io](https://blisk.io/)
- Safari RDM and Chrome Device Mode have one viewport, so no sync concept — [Apple docs](https://developer.apple.com/documentation/safari-developer-tools/responsive-design-mode); [Chrome docs](https://developer.chrome.com/docs/devtools/device-mode)

### Inferences
- Because the docs do not describe a leader indicator, the "leader" is implicit (the pane under the pointer). A native competitor could differentiate by visibly marking the driving pane and by exposing per-event-type sync toggles in a popover rather than a right-click menu.

### Gaps
- Polypane docs explicitly do not specify how the leading pane is indicated; no source found for Responsively or Sizzy either.
- No documentation found on whether Blisk's sync can be toggled per device.

## Key Question 4: How do device presets, workspaces/suites/projects and saved per-site setups work?

### Takeaway
Polypane uses numbered "workspaces" (⇧⌘1–9 to save, ⌘1–9 to apply) that store panes, layout, sizing and optionally URL, with nine built-ins (device labs, framework breakpoints); Responsively uses a Device Manager with "suites" that can be imported/exported and (in 2.0) each remember their own canvas arrangement; Sizzy is project-centric (projects restore devices, sessions and tools); Blisk groups devices by type in a left panel; Safari/Chrome keep flat preset lists (Chrome now grouped by form factor) with custom devices added in settings.

### Cited Findings
- Polypane workspaces save panes, layout, sizing, URL (when set as default tab), and sidebar/tab settings. ⇧⌘1–9 saves to slots 1–9; ⌘1–9 applies (auto-switching to a multi-pane layout). Default workspace for new tabs is the three-pane workspace; changeable via the "home" icon in the Workspaces panel or File > "Set current tab as homepage". Nine built-in workspaces include device labs, popular viewport sizes, iOS/Android devices, and breakpoints for Bootstrap, Material UI, Tailwind CSS and Bulma. The Workspaces panel gives "a visual overview", with save/restore/import/export. Image: `https://polypane.app/doc-img/workspaces.png` — [Workspaces](https://polypane.app/docs/workspaces/)
- Polypane panes are resized "by drag and drop, using device preset or using workspaces" — [Intro to panes](https://polypane.app/docs/intro-to-panes/); v31 added iPhone 18 and 5K presets — [Changelog](https://polypane.app/docs/changelog/)
- Responsively Device Manager: add/edit/remove devices and "group them into suites for specific projects or testing requirements"; import/export of custom device setups; 30+ built-in profiles — [GitHub README](https://github.com/responsively-org/responsively-app); 2.0 lets you "save a different arrangement for each preview suite" — [v2.0.0-beta.0](https://github.com/responsively-org/responsively-app-releases/releases/tag/v2.0.0-beta.0); a user question on where the Device Manager lives exists at [Discussion #1181](https://github.com/responsively-org/responsively-app/discussions/1181)
- Sizzy: "project-centric workspace model where users can restore entire setups including devices, sessions, and debugging tools"; project switcher (⌘P) shows repo path, dev command, package manager and Node version — [sizzy.co](https://sizzy.co/); "per-project workspaces" and "multiple isolated sessions for testing different auth states simultaneously" — [Sizzy comparison blog (updated 12 Jun 2026)](https://sizzy.co/blog/polypane-vs-sizzy-vs-responsively/)
- Blisk: left devices panel grouped by phones/tablets in collapsible groups — [Creating Blisk devices](https://blisk.io/blog/creating-blisk-devices)
- Safari: preset list plus a "Custom size" preset that auto-saves the last manual size — [Apple docs](https://developer.apple.com/documentation/safari-developer-tools/responsive-design-mode)
- Chrome: custom devices via Settings > Devices > "Add custom device" (dimensions, DPR, UA, device type: Mobile, Mobile (no touch), Desktop, Desktop (touch)); presets grouped by form factor since Oct 2026 — [Chrome docs](https://developer.chrome.com/docs/devtools/device-mode); [New in DevTools Oct 2026](https://developer.chrome.com/blog/new-in-devtools-october-2026)

### Inferences
- Only Sizzy ties setups to a code project (repo path, dev command); Polypane ties them to keyboard slots and optionally a URL; Responsively ties them to suites. None of the fetched docs describe automatic per-domain restoration ("open example.com → restore its last pane set"), which looks like an open opportunity.

### Gaps
- Could not confirm whether Polypane workspaces can be bound to a specific site/domain automatically (docs say URL is saved only "when set as default tab").
- Responsively's exact suite-switcher UI location (sidebar vs. toolbar dropdown) was not documented in fetched sources.

## Key Question 5: What do users praise or criticize (clutter, Electron feel, performance, pricing)?

### Takeaway
Praise centers on time saved and responsive developer support (Polypane, Responsively); criticism centers on subscription pricing (Polypane, Blisk), performance/slowness in Electron (Responsively on M1, Blisk with many devices, Polypane site lag), confusing advanced UI (Blisk), and Apple removing device icons from Safari RDM (Safari 17).

### Inferences
- The strongest recurring UX complaints that a native macOS app could target: (1) Electron weight/performance with many webviews, (2) subscription fatigue (a one-time Mac App Store purchase would read as a differentiator), (3) Safari's loss of quick device presets (WebKit-based native app could fill that gap with real WebKit rendering, which Polypane/Sizzy/Responsively cannot offer since they are Chromium-only).

## Key Question 6: Are there native (non-Electron) macOS tools in this category, and any new entrants 2024–2026?

### Takeaway
The only native macOS multi-viewport tool found is Solis (Cazoobi, Mac App Store, WebKit, up to 50 draw-and-arrange viewports), and its last visible version is 1.0.8 (~2021), so the native niche is effectively empty; the "new entrants" of 2024–2026 are not new products but major rewrites (Responsively 2.0, Sizzy 74/75, Polypane canvas) plus Chrome extensions.

### Cited Findings
- Solis for Mac: "real time, multi viewport previewing of HTML, CSS, SCSS and LESS"; "Draw, resize and arrange multiple viewports"; "up to 50 viewports simultaneously"; WebKit developer inspector per viewport; integrates with Atom, VS Code, Sublime, Brackets; developed by Cazoobi Software — [solisapp.com](https://solisapp.com/); [Blocsmaster on Solis](https://blocsmaster.substack.com/p/solis-app-for-mac); versions 1.0.7 (May 2021) and 1.0.8 listed on third-party download sites — [MacUpdate listing](https://solis.macupdate.com/)
- Ora Browser: open-source native macOS browser (SwiftUI + AppKit, WKWebView, "zero Electron bloat"), 2,000+ stars, roadmap includes split-view browsing with two tabs side-by-side — not a responsive-testing tool — [BrightCoding guide](https://www.blog.brightcoding.dev/2025/12/06/building-a-native-macos-browser-with-swiftui-the-complete-developer-guide-to-creating-the-next-generation-web-experience)
- Apple added a native SwiftUI WebView in 2025 (replacing NSViewRepresentable wrapping of WKWebView) — [TrozWare, SwiftUI for Mac 2025](https://troz.net/post/2025/swiftui-mac-2025/)
- Chrome Web Store extension "Responsive Website Testing Toolkit - Multiple Viewport Simulator" exists as a browser-extension alternative — [Chrome Web Store](https://chromewebstore.google.com/detail/responsive-website-testin/pahjcficmhfgjkdcdadnacjdiinpilmd)
- Product Hunt alternatives pages for Polypane and Responsively list only the established set (Responsively, Sizzy, Blisk, BrowserStack); no new 2025 launch surfaced — [Polypane alternatives](https://www.producthunt.com/products/polypane/alternatives); [Responsively alternatives](https://www.producthunt.com/products/responsively/alternatives)
- All third-party multi-viewport tools found are Chromium/Electron: Responsively is "Electron-based" — [GitHub README](https://github.com/responsively-org/responsively-app); Sizzy updated to Electron 44.2.0 — [Glink changelog](https://glink.so/kitze/sizzy/changelogs); Polypane uses Chromium (155 in v31) — [Polypane 31 blog](https://polypane.app/blog/polypane-31-canvas-layout-elements-panel-improvements-and-chromium-155/); Sizzy "uses Chromium" — [sizzy.co/features](https://sizzy.co/features)

### Inferences
- A native WebKit app would be the only tool rendering with the iOS Safari engine while showing multiple viewports; Solis proved the concept but appears unmaintained, and Safari RDM users explicitly asked for exactly the "quick presets + real WebKit" combination that Apple removed.

### Gaps
- Could not confirm Solis's current maintenance status or Mac App Store availability in 2026 (only 2021-era third-party listings found).
- No source confirmed Blisk's engine explicitly (reviews and feature set imply Chromium/DevTools, but the features page was not retrievable).
- Did not find any 2024–2026 native macOS launch in this category despite searching; treat "none exists" as absence of evidence, not proof.
